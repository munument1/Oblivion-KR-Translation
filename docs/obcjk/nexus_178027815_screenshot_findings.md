## 인코딩 증거와 한계

Python의 엄격한 GBK 디코더로 다음 두 오해석을 손실 없이 재현했다.

| 정상 문자열 | UTF-8 바이트를 GBK로 읽은 결과 | 배포 본명조 KR Medium의 cmap 지원을 적용한 표시 |
|---|---|---|
| 강철 흉갑 | 臧曥矤 頋夑皯 | 臧□□ □□□ |
| 작자미상 | 鞛戩瀽氙胳儊 | □戩□□□□ |

이는 사진의 글자·네모 배열과 일치한다. Windows의 실제 tofu 비트맵 자체는 이번 Linux 조사에서 재현하지 않았다. 네모는 font cmap의 미지원 위치를 뜻한다.

검사한 canonical FULL(Oblivion.esm:000229A2)은 정상 UTF-8 `강철 흉갑`이며, 저장된 OOO 원배포본과 grinder 핫픽스의 같은 레코드도 정상이다. UOP KR1.8의 BOOK DESC(00024564) 저자는 정상 UTF-8 `작자미상`이며, KR1.9에서 본편의 `작가 미상`으로 정렬되었다. obCJK의 확인한 UTF-8 렌더링 소스는 Unicode 직접 디코딩/GetGlyphOutlineW 경로를 사용한다. 따라서 사진만으로 현재 배포 DLL의 결함, 다른 플러그인, 구버전 파일, 실행 중 변환 가운데 하나를 단정하지 않는다. 사용자 답변상 Bashed Patch는 사용하지 않는다.

## 실제 아일레이드 문 연결

사용자 보관 과거 본편 ESM에서 ACTI 0001E7A5 `ARGate01`의 SCRI는 0004CAEE `ARGate01SCRIPT`였다. 해당 SCTX와 SCDA 모두 사진의 문구를 포함한다. 본편에는 UOP의 SewerVerticalGate01SCRIPT와 다른 원문 버전도 존재한다.

본편의 두 전체 SCPT body SHA-256과 고정 길이 변환 보고서는 `nexus_178027815_base_gate_validation.json`에 기록했다. 원본 보관 ESM은 이미 일부 번역된 파일이며 순정 전체 게임 검증의 증거가 아니다. 오직 해시가 일치하는 두 스크립트의 영어 payload와 전체 파일 역검증에 사용했다. 기존 CGSewerExitScript body 해시는 저장소의 기존 원문 핀과도 일치했다.

본편 생성기는 이 두 핀을 사용하며, UOP의 기존 세 핀은 별도로 유지한다. 알 수 없는 스크립트를 재컴파일하거나, 다른 모드가 수정한 스크립트에 추측성 패치를 적용하지 않는다.
